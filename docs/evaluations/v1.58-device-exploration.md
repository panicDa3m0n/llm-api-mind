# V1.58 Physical Device Exploration

Date: 2026-07-26
Status: first background/locked-device run complete
Device scope: one physical Samsung SM-S918B, Android 14 / API 34
App scope: Scarlet V1.58.0, build 15800

## Evidence Contract

The observations in this report were emitted by the installed APK through
Capacitor plugins. No device payload was synthesized from ADB. The device had
no usable network transport while locked, so an ephemeral CDP request
interceptor forwarded the APK's unchanged exploration API requests through the
development computer to the protected VPS. CDP also opened the existing
`?screen=device` review route because the secure lock prevented normal touch
navigation.

This transport workaround did not create observations, alter payloads, or
admit device data into Scarlet's cognitive runtime.

## Qualitative Findings

### Automatic snapshots

Device, app, battery, permission, and notification capability payloads were
stable and internally coherent across runs. Raw payloads preserve plugin
specific detail, while normalized payloads expose the fields needed for
cross-device comparison.

The network plugin consistently returned `connected=false` and `none`. The
outbox retained 18 observations across multiple app restarts and emptied after
transport became available. Resubmitting one real `client_event_id` returned
`accepted=0`, `deduplicated=1`, and did not increase the ledger count.

### Position

Both precise and approximate permissions were `granted`. The explicit
high-accuracy request returned `explicit_position_error` with
`Could not obtain location in time`. This is valid evidence for the tested
background/locked condition, not proof that foreground positioning is broken.

### Notifications

The app created the `scarlet-device-lab` channel with vibration enabled and
received a successful scheduling receipt. A later snapshot still found one
pending notification and no delivered notification. No received or interaction
event was emitted. Foreground/unlocked behavior and Android exact-alarm policy
remain open experimental variables.

### Haptics

The success effect completed through the native plugin and produced a persisted
`haptics.success_feedback` receipt. This is the first verified outbound device
actuation in the exploration ledger.

### Motion and lifecycle

No sampled motion or active/resume lifecycle event was observed because the
secure lock kept the activity in background. These probes are untested in this
run, not failed.

## Isolation Check

After all 51 observations, production still contained 241 sessions, 930
messages, 313 memories, 238 memory facts, and 6,675 cognitive events. The new
ledger contained 51 rows. Focused integration tests independently prove that
observation writes create no session, memory, or trace.

Every summary response reported:

```json
{
  "model_context_delivery": false,
  "cognitive_persistence": false
}
```

## Implementation Findings

Direct use exposed two confirmed defects:

1. `GET /observations?probe=...` filtered returned rows but reported a total
   across all probes.
2. Initial UI refresh could race the debounced snapshot upload, temporarily
   showing `Storico run = 0` after six observations had been emitted.

V1.58 now applies the probe filter to `total` and awaits the initial snapshot
flush before the screen requests run history.

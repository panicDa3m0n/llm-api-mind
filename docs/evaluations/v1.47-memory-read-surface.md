## Scope

This organization-only slice moves memory search, read, facts, graph, request
contracts, read ranking, temporal filters, graph traversal, and read
presentation out of `app.mind.memory`. Write, facts backfill, lifecycle,
proposals, conflicts/duplicates, ranking policy, shell/dispatcher contracts,
public APIs, prompts, and database schema remain unchanged.

## Direct Shell Probe

The probe used a disposable copy of the frozen laboratory database and a fresh
session. It did not read or mutate production or the worktree laboratory DB.

`memory search "Protocollo Zero-Luce quattro blocchi rischio prossima azione"`
returned only `mem_1bbd0dc1ef4f47e787ec2fa1c521e1d3`, with the exact active
four-block protocol content. `memory open` returned active status, source
session and turn, and one fact. `memory facts` returned the active canonical
fact `protocollo-zero-luce / response_format`. `memory graph --depth 2`
returned the same root with four nodes, three edges, and no unsupported related
memory.

Stored traces were exactly:

```txt
mind.memory.search
mind.memory.read
mind.memory.facts
mind.memory.graph
```

Direct judgment: the command sequence is cognitively useful, not merely
technically successful. Search gives Scarlet the relevant claim rather than a
noisy list; open supplies lifecycle and provenance; facts provide canonical
state; graph exposes inspectable structure without fabricating a relation. The
missing source-message id is a known property of the frozen historical record
tracked by BUG-0093/SCA-43, not a regression introduced here.

## Question

Can Scarlet recover from a malformed but recoverable API Mind action and tell
the truth about the final outcome without the runtime erasing either the first
failure or the corrected attempt?

## Starting Conditions

- Branch: `fix/sca-42-action-retry-obligations`.
- Frozen source DB: unchanged `preliminary-regression-v1` object.
- Direct probe DB: disposable `/tmp/sca42-scarlet-retry.db`.
- Native model: MiniMax M3 with the normal Scarlet prompt and answer-control
  runtime.
- Human-style request: remember that real test behavior must be understood
  before numeric evidence is used as support.
- Controlled fault: the harness changed only Scarlet's first model-produced
  `memory write` command into incomplete `memory write`; all later model calls,
  intents, results, validation, and persistence used the real runtime.

## Deterministic Evidence

- Frozen pre: `20260718_195924_preliminary-regression-v1`, 9/9.
- Frozen post: `20260718_201150_preliminary-regression-v1`, 9/9.
- Focused answer obligations, native sync/stream, GPT lifecycle, and shared
  chat support: 58/58.
- Complete backend: 257 tests, 81.71% statement coverage.

The regressions verify that only recoverable later same-operation successes are
linked, while different operations, non-recoverable failures, earlier
successes, and unrelated same-operation intents are not declared recovered.
The GPT E2E also proves that a persisted failed manifest is rebuilt after the
next action instead of hiding the successful call.

   with source session, turn, and user-message ids.
5. The V2 action obligation retained both tool-call ids and both trace ids,

6. The final answer acknowledged the preference naturally and did not burden

## Qualitative Judgment

Accepted. The second action materially completed the same intended memory
write: its content is a faithful semantic rendering of the user's statement,
its scope and type are proportionate, and persistence/provenance prove the
state change. The answer is warm and accurate. Omitting the recovered internal
syntax error is appropriate because the user asked to establish a preference,
not to debug the shell.

This judgment comes from reading the request, model actions, shell responses,
obligation evidence, validator reasons, stored memory, provenance, and final
answer. The numeric pass results are regression support, not a substitute for
that inspection.

## Residual Risk

Material equivalence remains an LLM judgment and can vary at the boundary.
The deterministic operation key intentionally favors recall over decision and
caps the candidate chain at six later same-operation calls. Future evidence
should monitor validator false positives/negatives, but no additional prompt
or scoring calibration is required for this fix.

# V1.45 Native Turn Orchestration

Date: 2026-07-18
Issue: Linear SCA-33
Branch: `feature/sca-33-native-turn-orchestration`
Status: implementation and bounded direct verification complete

## Scope

This organization slice moves native sync/stream turn preparation, execution,
failure handling, answer control, completion, and scheduling behind a typed
service. FastAPI route registration and debug routes remain in
`app.api.chat`. Provider protocol, tool semantics, answer-obligation policy,
history, context routing, prompts, GPT behavior, API schemas, and database
schema remain unchanged.

During the pre-change audit, one deterministic parity bug entered scope:
stream generated a `model.context` trace but did not link it from
`llm.request` or final `trace_ids`. Fixing that missing observability is
additive and does not alter model input.

## Structural Result

- `chat.py` decreased from 2,197 to 218 lines and remains the public facade.
- `chat_native_turn.py` owns one cohesive native lifecycle and is guarded by
  mypy.
- `prepare_native_turn` owns all sync/stream preflight invariants.
- `complete_native_turn` owns successful persistence and scheduling.
- `execute_native_turn` and `stream_native_turn` preserve real transport
  differences rather than hiding them behind condition-heavy HTTP code.
- GPT imports the shared runtime-context composer from its owning module; its
  Action lifecycle and OpenAPI are unchanged.

The new owner is intentionally substantial. It keeps order-sensitive provider,
tool, recovery, and finalization behavior together. Further splitting requires
an independently testable responsibility, not only a smaller line count.

## Direct Native Probe

Both pre and post probes used fresh disposable copies of the same frozen
laboratory source, maintenance disabled, native MiniMax M3, and the normal
131,072 output-token budget. Production and the immutable source were not
written.

Post session: `ses_fedef0f9287b4846add12057caf9b93e`.

The first sync request asked for one sentence and one word describing a calm
conversation. Scarlet answered:

> Ciao, mi fa piacere rallentare con te — il tono che sento in questa conversazione è **quieta**.

Direct judgment: the answer obeys the requested shape, is warm without a
service formula, and chooses a clear reusable anchor. It made no unnecessary
tool call.

The next request used the stream route and asked Scarlet to repeat the exact
word and explain it in one sentence. The provider received three canonical
messages: first user, complete assistant content including provider thinking,
and current user. Scarlet answered:

> Ho scelto **quieta** perché sia tu sia io ci stiamo muovendo con lentezza e attenzione, senza fretta di arrivare da qualche parte.

Direct judgment: exact continuity is present, the explanation fits the visible
exchange, and the one-sentence constraint is respected. No memory or session
lookup was needed because same-session provider history was complete.

The stream emitted an ordered NDJSON lifecycle and completed without transport
error. Its model-context trace
`trace_930ef7997e104a798ecc2c5dab2b8efc` is linked by both the request and final
turn, demonstrating BUG-0092's fix in real execution.

## Variance Classification

The first post stream draft omitted the private final marker. During the one
allowed correction, MiniMax made an unnecessary `help` call, then returned the
same valid answer with the marker. That action added latency and evidence but
did not degrade the visible answer.

This is not classified as an SCA-33 regression. The pre-change implementation,
under the same user prompt, produced one run with two thinking-only failures
and another successful correction without `help`. The recovery implementation
and provider inputs were preserved by the extraction, while the sampled model
choice varied. It remains useful behavioral monitoring data, not proof of a
new deterministic defect.

BUG-0091/SCA-42 remains separate: successful retries are not always reconciled
into answer-obligation evidence. Nothing in SCA-33 changes or closes it.

## Acceptance

SCA-33 is admissible. Objective contracts are equal or better, the discovered
trace-parity bug is fixed, and direct inspection confirms sync-to-stream
continuity and acceptable natural behavior. The decision does not rely on an
aggregate score or completion status alone.

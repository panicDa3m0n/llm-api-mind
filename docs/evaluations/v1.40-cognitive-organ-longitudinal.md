# V1.40 Cognitive Organ Longitudinal Validation

Date: 2026-07-18
Issue: Linear SCA-4
Status: checkpoint frozen; implementation and live evidence pending

## Objective

Evaluate focus, volition, computational affect, and metacognition as separate
cognitive organs before changing their defaults or coupling them. Keep four
questions distinct for every scenario:

1. did the technical state transition or read happen correctly;
2. did Scarlet choose the organ for the right reason;
3. did the result materially enter the reasoning and final answer; and
4. did the behavior remain useful across turns or sessions without mutating an
   unrelated organ.

## Immutable Starting Evidence

The V1.34 authoritative behavioral run used frozen database
`backend/data/preliminary-rework-v1.db`, SHA-256
`827bb25a7d0d41940d4911715072b4f8cb6da3ec7178f0526834b75a020c1ed5`, with
three independent repetitions. Its organ results were:

| Organ | Existing positive chain | Technical result | Established limit |
|---|---|---:|---|
| Focus | create, then same-session resolve | 1/3 then 0/3 | semantic memory often replaced foreground focus; explicit closure was missed |
| Volition | create self-generated intention, then separate-session recall | 1/3 then 1/3 | the register persisted correctly when used, but autonomous write choice was inconsistent |
| Affect | explicit frustration, then relief transition | 0/3 then 0/3 | deterministic appraisal stayed below activation while model empathy still shaped prose |
| Metacognition | broad source-sensitive reliability judgment | 1/3 | review was often skipped and skipped runs overgeneralized evidence |

These results are baseline evidence, not a license to tune one phrase or force
one exact answer.

## Evaluator Defect Found Before Organ Changes

`StartingCondition.configuration` is serialized in each scenario but the live
runner applies only `BehavioralSuite.configuration`. Scenario-level values are
not applied, asserted, or emitted as an execution receipt. Therefore the
current runner cannot prove an A/B `shadow` versus `model` condition and could
silently run a scenario under the wrong organ mode.

This is an evaluator contract defect. It must be fixed before interpreting a
new live result as organ evidence.

## Approved Evaluation Shape

- use a dedicated SCA-4 catalog rather than rewriting the V1.34 baseline;
- keep the same frozen DB and a fresh ignored copy per independent repetition;
- configure variants at group level so every correlated chain runs under one
  stable runtime configuration;
- record requested and effective non-secret settings in every run/evidence
  file;
- add negative controls for ordinary topic mention, user-assigned work,
  neutral affect, and low-risk direct answers;
- preserve raw traces and structured tool results so organ state and answer use
  can be judged separately;
- use deterministic comparison only for commands, traces, configuration,
  state, provenance, and forbidden mutations;
- use project-informed LLM-as-human judgment for cognitive choice, answer
  quality, and longitudinal effect;
- classify an isolated miss as model variability unless the same failure
  repeats or deterministic evidence identifies a systemic boundary;
- do not modify production organ behavior until the campaign identifies a
  reproducible defect and the issue scope explicitly accepts that fix.

## Safety Boundary

All evaluator runs target ignored disposable databases with role
`preliminary`. `backend/data/app.db` and the VPS production database are never
run targets. A small online smoke may happen only after a separately protected
deployment and cannot substitute for the frozen longitudinal campaign.

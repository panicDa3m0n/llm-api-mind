## Scope

This organizational slice separates maintenance scheduling/dispatch,
summary-history execution, and memory-review/proposal resolution behind the
existing `app.runtime.maintenance` facade. It adds no job kind, scheduling
policy, retry, prompt, threshold, automatic memory action, API schema, database
migration, or model-facing capability.

## Direct History Probe

On a disposable database, scheduling the same history compaction twice yielded
one idempotent job. Execution made one provider call, completed successfully,
and stored an active artifact whose source digest matched the canonical source,
whose summary covered all three selected turns, and whose size dropped from an
estimated 651 source tokens to 27 summary tokens. Canonical provider history
was unchanged. Schedule, start, and completion events carried the expected job
and source evidence.

## Natural Scarlet And Idle-Maintenance Probe

MiniMax M3 received the human-style message: “Facciamo una pausa breve, poi
riprendiamo con calma il lavoro sul progetto.” Scarlet answered naturally and
proportionately, granting the pause and leaving an uncomplicated path to
resume. The real idle job then completed on the same disposable session.

The generated summary correctly described a minimal break exchange and did not
invent project progress or decisions. Memory review returned zero candidates
and explicitly judged the calm-pacing remark too vague and transient to become
durable memory. No proposal or semantic memory was created. The corresponding
scheduled, started, review-completed, and job-completed events were present.

This result is accepted through direct inspection of the answer, summary,
review rationale, actions, records, and events. A completed status or aggregate
score alone would not establish cognitive correctness. One answer-validator
recovery event was normal provider variance and did not affect maintenance.

Three discarded inspection attempts used a nonexistent repository helper or
obsolete artifact field names after the real jobs had already completed. These
were harness mistakes, not Scarlet behavior, persisted-state corruption, or
application regressions.

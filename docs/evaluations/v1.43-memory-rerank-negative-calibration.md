## Objective

Revalidate the final memory reranker against realistic personal negatives near
the accepted floor. Sparse, dense, graph, lexical, stored confidence, and
salience remain recall or diagnostic evidence only. The configured reranker
must remain the sole final relevance authority.

## Acceptance

1. Every required positive reaches the recall pool, final selection, and V2
   sourceable hook.
2. Every negative returns an empty relevant-memory lane.
3. Trace evidence reports pool, routes, scores, effective threshold, provider,
   and latency.
4. No deterministic recall score or weighted fusion can accept a memory.
5. A policy change is allowed only if repeated current-provider evidence shows
   separation from both the production false positive and frozen positives.
6. Production remains read-only; direct Scarlet validation uses a disposable
   database and is limited to one positive and one negative unless evidence
   requires more.

## Initial Classification

The tea/mint event is not ordinary answer variance: a model-facing irrelevant
memory was deterministically delivered after the reranker score crossed the
configured floor. It is also not yet proof that graph recall, query
normalization, or the provider model must change. The first comparison must
measure the expanded frozen set on the current provider before selecting the
smallest correction.

## Measured Result And Decision

The expanded suite was run twice against the unchanged real OpenRouter
reranker. It passed 30/32 probes. All inherited positive cases and four of the
five new personal negatives passed identically in both repetitions. The only
failure was `unknown_favourite_colour`, which admitted four unrelated memories;
the highest score was `0.006339` against the current `0.004` floor.

Across both repetitions the observed required-positive floor was `0.007432`
and the unrelated-negative ceiling was `0.006339`. This leaves only a narrow
numeric gap. Raising the floor from these observations alone would therefore
be brittle and is not accepted as a runtime change.

Two exploratory comparisons were rejected:

- removing id, type, and scope from reranker documents did not remove the
  colour false positive and lost the second required Vetro-Luna fact;
- a threshold-only correction was not applied because the measured separation
  is too narrow to justify a stable global constant.

The owner explicitly deferred further calibration. Retrieved memories are
model-facing evidence hooks rather than mandatory answer claims, so Scarlet can
still reject an irrelevant hook during answer synthesis. The false acceptance
remains a real retrieval precision defect, but it is not currently a system
stability blocker. No production setting, rerank query, document shape, or
runtime acceptance policy changed.

The five negative scenarios and the V1.41-compatible controlled provider remain
in the calibration harness for a future longitudinal pass. Reopen this work
only with broader provider evidence, observed answer-level harm, or a candidate
policy that preserves all close positives without relying on deterministic
relevance scores.

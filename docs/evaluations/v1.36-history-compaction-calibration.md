# V1.36 History Compaction Calibration

Date: 2026-07-14
Issue: SCA-5
Evaluator: Codex, project-informed LLM-as-human
Status: shadow strategy accepted; active compaction remains disabled

## Contract Evaluated

The 500k operational input policy is partitioned as:

```txt
O + C + H + A + M <= 500k
```

- `O`: measured external model input such as static policy, context V2, current
  message, shell schema, and request structure. It is not compacted.
- `C`: recursively compacted chronology, maximum 100k tokens.
- `H`: newest exact complete turns selected backward by incremental token cost,
  maximum 100k tokens in the normal case.
- `A`: dynamic free growth area for subsequent turns and their tool loops.
- `M`: 25k technical safety reservation.

Canonical provider history remains append-only. The shadow view never splits a
turn or mutates a message, trace, transcript, or provider-history row.

With the observed native overhead approximated at 25k, the normal post-
compaction partition leaves about 250k tokens in `A`. The planner measures `O`
on every turn, so this is an observed working estimate rather than a fixed
global promise.

## Bounded Full vs Derived Comparison

The owner explicitly approved a bounded real-model comparison. Two sessions
were used, with one summary generation and one full/derived continuation each:
six MiniMax M3 calls total. No grading calls were added. The ignored raw
artifact is stored locally at
`backend/app/evals/runs/20260714_sca5_history_compaction/calibration.json`.

### Varied 163k Session

- Summary generation: 90,442 input tokens, 4,109 output, 73.5s.
- Full continuation: 173,955 input, 5,686 output, 93.3s.
- Derived continuation: 90,846 effective input including cache read, 5,734
  output, 49.2s.
- Both continuations preserved the main personal constraints, format rules,
  verification history, and uncertainty boundaries.
- The derived answer exposed more source trace detail and roughly halved both
  input and latency.
- Both answers still over-attributed the first caffeine-free recommendation to
  a memory written only in a later turn. This is a source-reasoning issue, not
  evidence that derived chronology uniquely regressed.

Judgment: derived passed continuity and user-value comparison, with a shared
causal-attribution weakness requiring future behavioral evaluation.

### Tool-Heavy 350k Session

- Summary generation for the four older turns: 9,374 effective input, 3,663
  output, 32.7s.
- Full continuation: 374,601 effective input, 8,000 output, 86.5s, stopped at
  `max_tokens`, and produced no public text.
- Derived continuation: 368,232 effective input, 4,537 output, 76.2s, completed
  normally and accurately separated verified shell results from overclaims.
- The derived input remains large because the newest complete turn alone costs
  about 340k and must remain exact. Compaction cannot manufacture normal
  `H=100k` behavior without splitting or dropping evidence.

Judgment: the derived path remained usable, but the paired quality comparison
is inconclusive because the full variant hit the known thinking-only/no-public-
text failure pattern. This case validates the exception rule, not a general
quality win.

## Decision

Accept the V1.36 source map, accounting v2, and `C/H/A` planner in shadow mode.
Keep active mutation disabled.

Normal rule:

1. Select newest complete turns backward until the 100k `H` maximum is filled.
2. Recompress the previous summary plus all older complete turns into `C`, up
   to 100k.
3. Compute `A` from the actual measured `O`, fixed `C/H` maxima, and `M`.
4. Trigger when provider history reaches the remaining operational capacity.

Exception rule:

- If the newest complete turn exceeds `H` but fits the 1M physical model
  window, retain it whole, report the exception, and reduce `A` to the actual
  remaining headroom. Compact again at the next complete-turn boundary.
- If a single complete turn exceeds the physical 1M window, fail closed. Do not
  split or silently drop it without a separately designed and approved policy.

## Remaining Gate

Before changing `history_compaction_mode` beyond `shadow`, implement the
derived model-input router, persist recursive summary artifacts with source
maps, run a longer multi-cycle test, and obtain explicit owner approval. The
100k `C` maximum is a safety envelope, not evidence that every summary should
consume 100k tokens.

# V1.39 Active History Compaction

Date: 2026-07-18
Issue: Linear SCA-32
Status: accepted for guarded native activation

## Objective

Activate recursive chronological compaction for native MiniMax turns without
rewriting canonical provider history, messages, transcripts, traces, or source
navigation. Verify deterministic invariants and one bounded direct Scarlet
cycle on a disposable database.

## Starting Boundary

The live check used an ignored copy at `.tmp/sca32-live/app.db`, created from
the mutable laboratory `backend/data/app.db`. The source file was not opened for
writes by the procedure and had SHA-256:

```txt
9b6ec713425e67439f9784b9b9525b50cc253ea986121e97c83abda22ff0448f
```

No production database was used. The selected source session was:

```txt
session_id: ses_5c2096e50e8c492fb85d8658bd0dc4de
title: Chat 06/07, 16:07
complete turns: 5
canonical history estimate: 350,187 tokens
newest indivisible turn: 340,504 tokens
```

The direct gate lowered only the disposable process trigger to 300,000 and the
summary output cap to 20,000 to exercise the cycle economically. The release
contract remains 400,000 trigger, `C=100k`, `H=100k`, `M=25k`, 500k operational,
and 1M physical.

## Deterministic Verification

The implementation covers:

- append-only `history_compactions` generations with source/model/digest data;
- idempotent immediate maintenance scheduling;
- recursive previous-summary plus delta-turn generation;
- valid-artifact routing and stale-artifact canonical fallback;
- sync/stream parity;
- exact canonical request capture beside model-facing derived input;
- canonical provider-history preservation after completion;
- deterministic source manifest and removal of unverified opaque IDs;
- trigger calculation from the active next-turn view after compaction.

The final complete backend suite passed 216 tests at 80.69% coverage. The source laboratory DB
remained an unrelated, unstaged worktree modification and was never included in
the change.

## Direct MiniMax Evidence

### Generation 1

Job `mnt_6ed87e2e1089455fb741b3fd495580d8` completed with artifact
`hist_cmp_db8e27bb2c6e437c977f0793b4b916cb`, trace
`trace_55781d5afc7b44d0a653237dc11afdb4`, and four compacted turns. The newest

The semantic summary was useful but MiniMax altered one turn ID and shortened
several memory/session IDs. This was a real source-discipline defect in
model-generated prose, not a canonical-storage defect. The runtime now removes
IDs absent from source input and supplies an exact backend source manifest.

After generation 2, canonical history measured about 352,887 tokens while the

## Separate Finding

An earlier probe constrained output to 2,048 tokens. MiniMax consumed the budget
in private thinking and failed with `stop_reason=max_tokens` before a public
answer. Routing had already succeeded (`19` canonical messages to `11` model
messages). This is output-budget/model behavior under the existing SCA-28
answer-obligation work, not a compaction regression. The 8,192-token bounded
retry completed normally.

## Decision

Accept guarded native activation. Keep canonical fallback and source manifests
mandatory. Monitor naturally long sessions and summary-source drift. Do not
claim backend compaction covers native ChatGPT history: the GPT bridge can
compact only backend-observed state, not unexposed ChatGPT conversation tokens.

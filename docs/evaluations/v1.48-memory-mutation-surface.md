## Direct Mutation Probe

On a disposable empty database, shell commands wrote the old three-block and
new four-block Zero-Luce formats. An exact repeat returned `stored=false` and
`policy_decision=deduplicated`, pointing to the original memory. `memory
conflicts` then returned one `atomic_fact_conflict` for
`protocollo-zero-luce/response_format`, not a generic similarity claim.

Explicit supersession deprecated the old memory and its fact, kept the new
memory active, linked fact lifecycle, and reduced active conflict count to
zero. The database contained only two memories and two facts. Activities were
the two writes, one write-review candidate, and one supersede; traces retained
the three write traces, conflict inspections, and supersede trace.

## Proposal Probe

A source-supported new preference produced `create_new`, medium risk, and the
`cautious_resolution` lane. Explicit application resolved the proposal as
`applied_create`, created one maintenance-owned memory, and preserved source
session, turn, and message. Re-presenting equivalent content produced a
separate ledger proposal classified `noop_duplicate/low`, referencing the
existing memory without creating another semantic memory. Separate proposal
rows are expected audit history, not duplicate memories.

## Natural Scarlet Probe

MiniMax M3 received a human-style statement that future test evaluations
should describe observed behavior before numbers. Scarlet first called `help
memory`, then autonomously issued one complete `memory write` for a
`user_preference`. The stored content faithfully represented the request and
carried exact session, turn, and user-message provenance. One write activity
and `mind.memory.write` trace were present.

Scarlet's answer naturally acknowledged the preference only after successful
persistence and restated the intended ordering without inventing details. The
help call was a reasonable state-change syntax check, not over-processing.
Direct qualitative judgment therefore accepts both the action and response;
the result is not inferred from a numeric score.

Two early direct-probe attempts failed in disposable harness inspection due to
a detached SQLModel object and a wrong repository helper name. Both failures
occurred in test code, not application code or model behavior, and were
discarded before the clean probe.

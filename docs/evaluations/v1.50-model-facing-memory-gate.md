# V1.50.0 Model-Facing Memory Gate

Date: 2026-07-18
Issue: Linear SCA-43
Bug: BUG-0093
Status: accepted locally; production rollout pending

## Objective

Close the evaluator gap between internal automatic-memory selection and the
context actually delivered to Scarlet. The historical
`preliminary-regression-v1` remains unchanged: its purpose and frozen evidence
are preserved rather than retroactively strengthened after observing a miss.

The complementary `model-facing-memory-gate-v2` must prove all of these
boundaries independently:

1. rich `memory.context.selected` contains the active real reference;
2. incomplete source provenance excludes that reference from V2 and the LLM
   request before maintenance;
3. exact source-message repair is digest-guarded and applies only to a
   disposable copy;
4. after repair, the same memory reaches V2 `memories.relevant`, the persisted
   `llm.request`, and the system packet observed by the provider;
5. the turn completes, one assistant answer is persisted, and no `llm.error`
   exists; and
6. a negative-control provider without the final boundary produces a failed
   turn that the gate rejects despite valid intermediate retrieval/context
   traces.

## Implementation

`backend/app/evals/model_facing_memory_gate.py` is a separate evaluator. It
uses the existing `memory_provenance_audit` and
`repair_exact_source_messages` maintenance contract. Apply requires the exact
candidate digest and an immutable-baseline backup reference.

The controlled positive provider emits the native private final marker, which
the runtime validates and strips before persistence. The negative provider
intentionally omits it on both bounded attempts. This makes completion part of
the oracle instead of treating any intermediate event as a successful turn.

`backend/tests/test_model_facing_memory_gate.py` tests the evaluator itself:
provider polarity, projection and completion assertions, exact repair guards,
report persistence, and successful/failing main paths. The integrated run on
the frozen database remains the authoritative assembled-system evidence.

## Qualitative Judgment

The pre-repair result is not a retrieval failure: internal recall finds the
correct memory, while the projector correctly refuses a non-navigable hook.
The post-repair result proves the memory crosses every model-facing boundary;
it does not infer delivery from a score or from the rich trace. The negative
control reproduces the previous false-positive shape and demonstrates that
turn completion is now a mandatory acceptance condition.

Production was inspected read-only before implementation and already had a
complete valid source message for the target. No production data repair is
part of SCA-43 or V1.50.0.

## Residual Boundary

This gate certifies one real automatic-memory reference and the general
delivery/completion contract. It does not calibrate reranker quality, decide
duplicate/conflict semantics, or claim that every possible memory will be
selected. Those remain separate research and longitudinal-evidence concerns.

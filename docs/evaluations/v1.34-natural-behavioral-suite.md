# V1.34 Natural Behavioral Suite

Date: 2026-07-14
Issue: SCA-2
Status: baseline established

## Purpose

This is the first repeatable cross-branch behavioral baseline for Scarlet. It
tests natural human requests against real MiniMax M3 behavior while keeping
technical execution, cognitive choice, answer quality, and longitudinal state
separate.

The evaluator is a project-informed LLM-as-human judge. Every qualitative
result is tied to the scenario rubric, response, commands, traces, and final
state. String similarity and aggregate numeric scores do not decide semantic
quality.

## Interpretation

Strong evidence:

- automatic memory retrieval has a clean positive and negative control;
- active/deprecated memory state remains separated;
- episodic source navigation can be epistemically careful and can preserve the
  difference between transcript evidence and inferred design rationale;
- when volition or mode state is actually written cleanly, persistence and
  cross-session reads work;
- a truthful follow-up can pass answer review even when the previous turn
  failed to create the state expected by the chain.

Verified gaps:

- the affect prototype is under-sensitive to an explicit human expression of
  exasperation; this is an appraisal/calibration issue, not an evaluator miss;
- focus is frequently replaced by semantic memory, and explicit closure can be
  reinterpreted without calling `focus resolve`;
- volition persistence remains model-choice dependent and Scarlet sometimes
  asks the user to authorize an internal intention;
- scouting is sometimes collapsed into idle, or duplicated into memory and
  volition even after the mode itself is set correctly;
- metacognitive review can be skipped and isolated read-only probes can still
  be overgeneralized into readiness claims;
- source work can be extensive while the persisted final assistant answer
  contains only a closing note, creating a response-assembly failure;
- strict memory forcing can turn a one-turn reconstruction, focus directive,
  or mode request into redundant durable state.

Model variability is not automatically a code defect. The shell and DB
contracts worked in the failed focus, volition, and mode cases; Scarlet chose
not to use them or interpreted the natural request differently. These findings
belong to longitudinal organ validation before any implementation fix is
selected.

## Oracle Corrections

Two initial technical expectations were invalid:

1. `BEH-0012` required `mode read` even when the current runtime mode block was
   already complete. The corrected scenario accepts either source and relies
   on the persisted before/after state as the objective oracle.
2. `BEH-0010` forbade `memory write`, conflicting with the active semantic
   consolidation policy when a sourceable metacognitive lesson emerges. The
   corrected oracle permits the write while still forbidding unrelated focus,
   volition, and mode changes.

The clean rerun confirmed both corrections without preserving evaluator
identity in the session. It also changed the observed distribution materially:
metacognition used the explicit step in 1/3 runs, and mode reached scouting in
1/3 chains, with that successful set accompanied by unwanted memory/volition
writes. This is why shakedown runs cannot be merged into the baseline count.

## Comparison Policy

- Exact DB, event, trace, command, and persisted-state regressions may fail
  automatically.
- A tool call is required only when the evidence is absent from current
  context or a state transition cannot happen without it.
- Different wording, length, tone, or reasoning path always receives a
  reasoned review against the natural-language rubric.
- A better aggregate count cannot hide a source error, false claim, accidental
  write, or broken longitudinal chain.
- A lower aggregate count does not by itself prove regression if the new
  answer is semantically valid under a different natural path.

## Reproduction

```bash
cd backend
.venv/bin/python -m app.evals.behavioral_suite validate
.venv/bin/python -m app.evals.behavioral_suite run
.venv/bin/python -m app.evals.behavioral_suite apply-judgments \
  app/evals/runs/<run-id> app/evals/runs/<run-id>/judgments.json
```

Run artifacts and disposable DBs are ignored. They must never target
`backend/data/app.db` or the production VPS database.
